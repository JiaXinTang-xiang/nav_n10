## 5. 航向角直行怎么纠偏

航向角统一成逆时针为正。原 AHRS yaw 的输出带负号，因此使用当前 `CHASSIS_ANGLE_YAW_SIGN=-1` 转换；最终符号以实车左转时显示的当前角 N 增大为判据。

```text
now  = WrapPi(YAW_SIGN × IMU_GetYawDeg() × pi/180)
error = WrapPi(reference - now)
corr_w = clamp(Kp × error, -0.35, +0.35)  // rad/s
```

误差绝对值 ≤0.30° 时纠偏量为 0。

```text
左轮控制目标 = 原左轮目标 - 轮距/2 × corr_w
右轮控制目标 = 原右轮目标 + 轮距/2 × corr_w
```

例如车体向左偏，当前角增大，误差为负，纠偏角速度为负，左轮目标相对增加、右轮目标相对减小，产生向右纠偏。不要把这一关系解释反了。

`WrapPi` 处理 ±180° 跨界，取最短角度差。此环保持朝向，不能消除已经发生的横向位移；六轴 IMU 的 yaw 也会随时间漂移，不能宣称具有绝对航向或无限时长直线保证。

## 6. 最新完成：正式上位机每段直行锁当前角

入口为 `Chassis_SetTwist(v_mps,w_radps)`。状态为 `s_angle_hold_en`、`s_host_straight_dir`（0 无正式直行段，+1 前进，-1 后退），参考角为 `s_angle_ref_rad`。

判定直行：`abs(v)>=0.001 m/s` 且 `abs(w)<0.0005 rad/s`。串口角速度的分辨率是 0.001 rad/s，所以协议中任何非零角速度都退出直行锁角，避免吞掉导航控制器的小转向。

| 场景 | 当前行为 |
|---|---|
| 新的一段直行 | 捕获当时 IMU yaw 为参考角 |
| 持续重复发送直行指令 | 保留原参考角，不每帧重置 |
| 同方向直行改变线速度 | 保留原参考角 |
| 非零角速度，包括很小的转向 | 关闭角度环和旧 gz 外环，执行上位机差速指令 |
| 零速度零角速度 | `Chassis_Stop()`，清除锁角状态 |
| 250 ms 通信超时 | 停车并清除锁角状态 |
| 直行前后换向 | 重新捕获当前角 |
| 转弯或停车后再次直行 | 重新捕获当前角 |
| 模式 6 切到正式直行 | 正式指令重新捕获，不沿用测试参考角 |

实现注意：`Chassis_SetWheelSpeed()` 会清除角度状态，因此 `SetTwist()` 在调用它之前保存是否需要保留参考角，调用后恢复正式直行状态。不能删掉这一步导致持续直行每次都重锁角。

`Chassis_Stop()`、`Chassis_Brake()`、开环 PWM 接口均清除正式直行状态。正式 `SetTwist` 全程不使用模式 3 的 gz 阻尼。

## 8. 串口协议保持不变

USART2 PD5/PD6，115200。速度帧 7 字节：

```text
BB v_hi v_lo w_hi w_lo checksum 55
```

v、w 均为有符号 int16 大端，单位分别 mm/s、mrad/s；checksum 为第 1～4 数据字节求和取低 8 位。合法帧通过缓存由 200 Hz 底盘任务应用，250 ms 无合法速度帧自动停车。

里程计 50 Hz 发 15 字节：`CC` + x_mm/y_mm/theta_rad 三个 float32 小端 + 数据字节求和校验 + `55`。

最新改动没有修改协议，也没有把 IMU yaw 塞进里程计 theta；当前 theta 仍由编码器差速积分产生。

## 11. 待核查问题：本轮没有修，不要误以为已解决

### 已确认：里程计三角函数近似有错误

`Chassis_task.c` 的 `SinCosApprox()` 中：

```cpp
num = x * (CHASSIS_PI - x);
*s = sgn * (4.0f * num) / (CHASSIS_PI * CHASSIS_PI + num);
*c = (CHASSIS_PI * CHASSIS_PI - 4.0f * num)
     / (CHASSIS_PI * CHASSIS_PI + num);
```

当角度为 pi 时，num=0，算出 cos=+1，实际应为 -1；当前公式无法得到正确的负 cos。sin 公式也不是正确的 Bhaskara I 表达式，pi/2 时算得 0.8，而实际为 1。源码“误差 <0.2%”的注释不能相信。

这意味着直线朝向 0 时可能看似正常，转弯后 x/y 明显错误。下一位 AI 应先确认工程数学库链接条件，修成正确 sin/cos 实现，并用 0、±pi/2、pi 及整圈采样验证，随后再进行里程计实车标定。本次交接没有修改这个函数。

### 编码器 A 相捕获解码仍需核查

只在 A 相双边沿触发中断，但 `Encoder_CaptureIRQ()` 当前用相邻 AB 四状态转换判断方向。A 相两次中断之间 B 相也可能变化，不能直接套用每个 AB 边沿均采样的假设。需要结合波形和手转轮子计数验证；本轮没有重新设计解码。

`Encoder_TakeIsrCount()` 目前取走并清零的是 `s_raw_count`，不是独立边沿计数器，可能污染正常里程计增量。现有活动页面未调用 `Chassis_DebugDisplayIsr()`，不要未修这个问题就把该诊断页接回运行路径。

### IMU 零偏和采样时序

当前零偏更新根据 gyro 低方差和计数条件判断，恒定转动也可能低方差，可能误当静止并更新偏置。若转弯或长时间运行后 yaw 异常，检查这里。

IMU 解算在包含 OLED 刷新的主循环内，尚无独立固定采样调度、数据新鲜度检测或故障退出锁角逻辑。若角度更新慢或数据卡住，需要测采样周期和 OLED 开销，不能仅依据底盘控制任务 200 Hz 就认为 IMU 也在 200 Hz 更新。

上述后两类是需要定位的风险，不是本次实车证实的新故障。不要不看数据就大范围重构。
