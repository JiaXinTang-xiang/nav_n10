# 底盘里程计重新验收

> 状态（2026-10-06）：STM32 板端验收已完成，编码器计数、方向、静止抗干扰、
> 直线数量级及旋转角度均已实测确认。底盘参数现已冻结，可进入 ROS/SLAM 验收。

本轮修改不再通过 Cartographer 参数掩盖轮计数问题。参考成熟两轮差速底盘后，当前工程改为：

- STM32 保留左右轮独立累计计数；
- 串口遥测附带 MCU 时间戳、序号、左右累计计数；
- ROS 发布 `/wheel_counts`；
- ROS 可根据累计计数差积分 `/odom`；
- 左右轮 `meters_per_count` 独立配置；
- 编码器输入捕获滤波从 4 调到 8。

## 1. 烧录后的第一轮测试

先不要启动 SLAM，也不要让电机转动。在非电机测试页面长按 USERKEY，可直接进入模式 7，进入时自动清零：

```text
ISR L,R : 左右 A 相边沿频率
cnt L,R : 左右累计有符号计数
d mm    : 左右累计距离
th deg  : 不回绕的累计轮式 odom 角度（度）
```

轮子静止 30 秒：`ISR L,R` 应稳定接近 `0,0`。若一侧持续有明显频率，该侧仍有电气噪声，不能继续标定。

在模式 7 中再次长按 USERKEY，可随时把 `ISR`、`cnt`、距离和 odom 全部清零，不必循环经过会驱动电机的测试模式。

模式 1/2/3/6 驱动电机时，长按 USERKEY 会立即停车并回到模式 0，
最终 `cnt` 和距离保留在 OLED 上，不会被清零。这样可以完全脱离 ROS 做底盘验收。

## 2. 每轮独立 10 圈测试

车架起、电机不通电，分别操作：

1. 长按清零，只把左轮向前手转 10 整圈，记录左轮最终 `cnt`；右轮应基本不变。
2. 长按清零，只把右轮向前手转 10 整圈，记录右轮最终 `cnt`；左轮应基本不变。
3. 每侧重复三次。

每圈计数：

```text
left_counts_per_rev  = abs(left_count) / 10
right_counts_per_rev = abs(right_count) / 10
```

把结果分别填入 `encoder.h`：

```c
ENC_LEFT_COUNTS_PER_WHEEL_REV
ENC_RIGHT_COUNTS_PER_WHEEL_REV
```

并在 ROS `chassis.yaml` 填入：

```text
meters_per_count = pi * 实测轮径 / 实测每圈计数
```

## 3. 判断问题属于哪一层

| 现象 | 结论 |
|---|---|
| 静止时一侧 ISR 持续增长 | 该通道电气噪声/悬空/接触问题 |
| 同样手转 10 圈，一侧计数每次都少很多 | 该侧漏边沿或编码器硬件问题 |
| 10 圈计数重复稳定，但左右数值固定不同 | 正常独立标定，不应强行取平均 |
| 手转正常，电机运行时某侧 ISR 异常增大 | 电机 EMI、线束或供电干扰 |
| 手转正常、开环同 PWM 时计数不同 | 两个电机实际速度不同，属于机械/电机差异 |
| 闭环相同目标速度时长期计数速度仍不同 | 速度反馈比例、PID 或饱和问题 |

## 3.1 2026-10-06 实测记录

静止 30 秒：

```text
ISR L,R = 0,0
cnt L,R = 0,0
```

左右轮分别手转 10 圈：

```text
左：7830, 7799, 7810 -> 平均 781.3 count/圈
右：7829, 7830, 7801 -> 平均 782.0 count/圈
左右每圈计数差约 0.09%
```

这两项通过，说明静止输入没有噪声，左右捕获和软件判向也具有良好重复性。

人工直推约 1 米：

```text
cnt L,R = 3984,3900
差值 = 84 count，约 2.13%
```

该次推行不是严格标定的 1 米，也没有严格保证轨迹笔直，因此只用于确认计数数量级，
不能用来反算轮径或左右距离比例。结合每轮独立 10 圈测试，编码器采集层判定通过。

## 3.2 板端附加测试模式（已完成，不作为当前待办）

1. **人工直推 2 米，重复 3 次**：每次从模式 7 长按清零，保持正常载荷，
   沿地面标线慢推。记录左右 `cnt` 和实际是否偏离标线。用三次平均值确定
   左右 `meters_per_count`，不要用单次 1 米数据直接定参数。
2. **模式 1 开环 PWM=20**：短按一次进入，运行一段固定地面距离后长按停车。
   记录最终 `cnt L,R`、车辆偏转方向。这一步只测电机/减速箱/机械差异；
   同 PWM 下左右计数不同是可能的，不作为编码器故障判据。
3. **模式 2 双轮速度闭环 0.2 m/s**：从模式 0 短按两次进入，运行相同距离后
   长按停车。记录运行时稳定的 `act L,R`、`pwm L,R` 和停车后的 `cnt L,R`。
   本模式 PWM 已限制在 ±30。稳定后左右 `act` 应接近 200 mm/s，累计计数差
   应明显小于模式 1。
4. 模式 6 用于单独检查 IMU 角度锁定。轮式 odom 本身仍只按左右累计计数积分，
   不会用 IMU 修改编码器累计距离。

## 3.3 转向 odom / 有效轮距标定（不接 ROS）

差速底盘的转角都按下面的公式计算：

```text
dtheta = (right_distance - left_distance) / effective_track_width
```

参考工程也在 ROS bridge 中使用相同公式，并把 `track_width_m` 作为独立标定参数。
实测外侧总宽 188 mm、胎宽 27 mm，得到几何中心轮距 161 mm。它仍只是初值；
轮胎接地点、胎面变形和原地旋转侧滑都会让有效轮距
与几何轮距不同。Cartographer 可以修正少量漂移，但不能替代系统性的轮距标定。

板端标定步骤：

1. 在正常载荷和建图时使用的地面上，给车体与地面画同一条起始基准线。
2. 长按 USERKEY 进入模式 7 并清零。
3. 绕两轮中心原地手动旋转正好 5 圈，实际角度为 1800 度，记录 `th deg`。
4. 顺时针、逆时针各做 3 次，记录带符号结果并分别计算绝对值平均数。
5. 按下式计算新有效轮距：

```text
new_track_width = old_track_width * abs(显示角度) / 实际角度
                = 0.161 * abs(th_deg) / 1800
```

例如实际旋转 5 圈而 OLED 显示 2100 度，说明当前 odom 角度偏大：

```text
new_track_width = 0.161 * 2100 / 1800 = 0.1878 m
```

最终有效轮距需要同时写入 STM32 的 `WHEEL_SEPARATION_M` 和 ROS 的
`wheel_separation`，两端必须一致。修改并重新烧录后，再转 5 圈验证 OLED 应接近
`+1800` 或 `-1800` 度。若顺、逆时针结果差异很大，应先检查轮胎侧滑、重心偏置、
地面差异和机械间隙，不能只用一个轮距参数掩盖。

首次实测：实际原地旋转约 360 度，模式 7 显示约 320 度，每侧累计计数约 1650。
依据角度比例先将有效轮距从 161 mm 修正为：

```text
161 * 320 / 360 = 143.1 mm
```

采用 `0.1431 m` 作为有效轮距后，用户已完成后续板端旋转测试并确认可用。
该值现作为 STM32 与 ROS 的统一标定值；若以后更换轮胎、改变胎压、载荷或主要地面，
才需要重新进行顺、逆时针旋转标定。

## 4. ROS 端验收

### 4.1 重新编译 ROS 工作区

重新编译后启动底盘桥：

```bash
cd ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select wheeltec_chassis lslidar_driver
source install/setup.bash
```

### 4.2 先只启动底盘桥

```bash
ros2 run wheeltec_chassis chassis_bridge --ros-args \
  --params-file src/wheeltec_chassis/config/chassis.yaml
```

另开终端检查：

```bash
ros2 topic hz /wheel_counts
ros2 topic echo /wheel_counts
ros2 topic hz /odom
ros2 topic echo /odom
```

数组内容依次为：

```text
[帧序号, MCU 100us时基, 左轮累计计数, 右轮累计计数]
```

底盘桥验收点：

- `/wheel_counts` 与 `/odom` 应约为 50 Hz；
- 帧序号连续递增，MCU 时间戳每帧通常增加约 200（单位 100 us）；
- ROS 中的左右累计计数应与 OLED 一致；
- 前进时 odom `x` 增加；逆时针转向 yaw 为正，顺时针为负；
- 实际旋转一圈时 yaw 会在 `+pi/-pi` 处回绕，这是 ROS 四元数的正常表现；
- `odom -> base_link` 只能由 `chassis_bridge` 发布一次。

### 4.3 再启动完整 SLAM

底盘桥单独验收通过后，停止单独启动的 bridge，使用工程根目录脚本：

```bash
cd <工程根目录>
bash ./slam_bringup.sh
```

该脚本按自身所在目录定位工作区，并使用
`ros2_ws/src/wheeltec_chassis/config/chassis.yaml`，不会依赖旧的固定工程路径。

SLAM 最小测试顺序：静止 30 秒、直行再返回、原地慢转一圈、走小矩形回到起点。
如果 `/wheel_counts` 和 `/odom` 正常但地图仍撕裂，再检查雷达时间戳、IMU、TF 和
Cartographer；不要重新改已经验收通过的编码器参数。
